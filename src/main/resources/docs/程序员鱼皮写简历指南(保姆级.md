问：⻥⽪⻥⽪，之前好像看你说过简历最好⼀⻚，那么如果⼀⻚实在放不下，第⼆⻚⼜只多出来五六⾏，这种是建议删掉⼀个含⾦量低的项⽬保留实习经历和另⼀个含⾦量更⾼的项⽬，还是有其他建议呢

答：简历最好⼀⻚指的是“少⼀些废话，⽤⼼凝炼内容”，证⾯试官有耐⼼看下去，⽽不是强制⼀⻚。只是希望⼤家在简历上突出重点、惜字如⾦，⽽不是像记流⽔账⼀样什么都写。如果你能写的内容就是很多的（⽐如冲击⼤⼚、⼯作3年以上、求职等级较⾼），那么⼀⻚纸以上完全没问题。

# 2. 简历优化

⼤家好，我是程序员⻥⽪。做知识分享这些年来，我看过太多简历、也帮忙修改过很多的简历，发现很多同学是完全不会写简历的、会犯很多常⻅的问题，不能把⾃⼰的优势充分展⽰出来，导致措施了很多⾯试机会，实在是很可惜。

如何在简历中增加亮点？

有哪些常⻅的简历问题？

如何利⽤写简历来提升⾃⼰？

在投递简历或者找他⼈帮忙看简历之前，请先把本专栏⼀字不差地完整阅读⼀遍，并且根据建议先⾃⾏修改简历，从⽽增加回复率。

对于不急着找⼯作的朋友，我也建议尽早准备⼀份简历，并且随着学习持续完善和优化，毕竟机会总是留给有准备的⼈。

这是专栏第⼆章：学习简历优化的技巧、避免踩坑。

我们写简历的⽬标是：在真实的前提下锋芒毕露，将有限的积累⽆限放⼤，向⾯试官表达出“我很主动、我⾃学能⼒很强、能够胜任⼯作、和贵公司的要求匹配”等信息，从⽽吸引⾯试官。

下⾯先分享⼀些基本建议，再分享⼀些⾼阶技巧（骚操作），最后分享⼀些常⻅的简历问题，帮助⼤家优化简历。

# 基本建议

1. 内容划分清晰、完整全⾯，简历通常包括⼏个部分：个⼈简介（基本信息、照⽚、学校、专业、成绩、四六级证书、特⻓介绍等）、竞赛奖项、个⼈技术栈、实习经历、项⽬经历、科研经历等。

2.合理划分各部分的⽐例，多写真实经历（实习、项⽬等），少写正确的废话（尤其是⾃我评价部分）

3.简历最好⼀⻚纸，内容超出时，过滤⼀些“废话”，只放最精华的部分。

4.简历的板块划分要清晰、排版要整洁、内容不要太挤或太空；⾊调不宜过暗或过亮，推荐蓝⾊或淡灰⾊；⾊彩不要太丰富，要让⼈看起来舒服。

5.明确你要找的岗位，简历上的所有内容尽量围绕这⼀个⽅向去写，突出重点。（⽐如你找后端⽅向的⼯作，即使你也会前端，也要注意不要让前端占了过多的篇幅）

6.依据个⼈优势对内容进⾏排序，把最有亮点的部分放上⾯，还可以适当对关键词进⾏加粗、调⾊等，突出⾃⼰的优势和亮点，尽量减少和其他同学简历的相似度。和短视频逻辑⼀样，⾯试官如果觉得你的简历千篇⼀律，⼀下就刷⾛了。

7.⽂字内容要精炼，拒绝⼝语化；⽤词尽量专业，体现专业性，不⽤担⼼⾯试官看不懂。

8.项⽬/实习经历介绍中，可⽤STAR分析（场景、任务、⾏动、成果）来梳理⾃⼰的核⼼⼯作。标准句式：在xx公司xx项⽬中，在xx情况下，运⽤xx技术，解决了xx，优化了xx，达到了xx效果，带来xx收益等。举个例⼦：为适应产品特性、加快迭代速度，后端由Springboot重构⾄Node.js，数据库由MySQL迁移⾄MongoDB，实现了前后⼀体的集中式配置中⼼，提⾼了接近1倍的开发效率。注意每段介绍不宜过⻓，留给⾯试官提问的空间。

9.简历项⽬中尽量不要出现重复的内容介绍（⽐如每个项⽬都写⼀遍使⽤Axios发送请求）。

10.最好给项⽬附上可直接访问的链接，有个⼈博客的话也最好写上去，建议多在博客中记录和总结⾃⼰学到的知识，让⾯试官感受到你的努⼒积累、脚踏实地。

11.写完简历后，⼀定要⾃⼰通读⼏遍，保证⾏⽂通顺、且⽆任何错别字！尤其是专业名词别拼错了！

12.有机会可以多阅读借鉴他⼈的简历，查漏补缺。

# ⾼阶技巧

# 1、引导

在写简历时，我们可以故意利⽤⼀些措词、加粗等⽅式来引导⾯试官。

⽐如很多⾯试官都会针对简历中提到的技术去展开提问。因此当我们介绍技术栈时，可以在⼀堆“了解”中适当添加“掌握”、“尤其熟悉”等词，⾯试官⼤概率会去问这些技术相关知识点。

此外，还可以细化你会的技术，⽐如把“熟悉多线程”改成“掌握多线程AQS、并发包等技术”，可以吸引⽕⼒，⼀定程度上防⽌⾯试官问到多线程中你相对薄弱的部分。在⾯试准备时间不⾜时，这个⽅法可能有奇效。

因此必须熟悉简历中的项⽬和⽤到的技术，提前想好对策。常⻅的问题有：

项⽬中⽤了哪些技术？

为什么⽤这个技术不⽤别的？

有什么亮点？怎么去优化等等？

现在⼤多数简历千篇⼀律，都说⾃⼰会Java、⼈均Java⼩能⼿，所以很难吸引到⾯试官。⽽如果你提到了Java中的某个⾼级知识点，有⼀定的学习深度，反⽽更容易被选中。就和我们平时刷短视频⼀样，⼀定是有什么东西吸引我们，才能看下去。

反之，如果简历很平淡，哪怕进⼊了⾯试环节，⾯试官可能也不知道问你什么，只能考各种⼋股⽂（胡乱开⽕扫射）。

# 2、适当包装

写简历的本质就是：如何以⼀种吹⽜⽪的⽅式表达出你的能⼒。

因此，虽然写简历要真实，但不能太⽼实！尤其是对于没有特别多项⽬的同学，要学会适当包装、合理包装。

⽐如将常⽤的技术进⾏组合、添加⼀些修饰词、使⽤⼀些专业名词等。

举个例⼦，本来写的是：使⽤了 MySQL 数据库、Redis 缓存、OSS 对象存储技术。

可以改为：使⽤ MySQL、Redis、OSS 三维⼀体的多元存储技术。

哈哈，虽说可能有⼀点点夸张，但还是能体现你的专业性的，不过不要乱吹就是了。

再举个例⼦：⽤xx框架提升了 $2 0 \%$ 的查询性能， $2 0 \%$ 是⼀个很不显眼的数字，如果你改成 $9 0 \%$ ，会更抓眼⼀些，并且对于⼤部分场合来说是合理的。

但是注意，杜绝欺骗！尤其是⼯作年限等有准确数字、可被调查的问题，请实事求是，否则后果⾃负。

# 3、定制化

根据不同的岗位、公司和JD（岗位描述）来调整优化简历（⽐如修改部分细节或⼯作内容），或者准备多份不同的简历。

⽐如你前后端都会，投递后端开发岗位时，把后端技术放在前端技术上⾯去写，项⽬经历、实习经历等都要侧重于后端。

# 4、⽤词不专业

简历上的每⼀个词汇，都能够反映出你的⽔平。

# 3. 问题和建议汇总

⼤家好，我是程序员⻥⽪。做知识分享这些年来，我看过太多简历、也帮忙修改过很多的简历，发现很多同学是完全不会写简历的、会犯很多常⻅的问题，不能把⾃⼰的优势充分展⽰出来，导致措施了很多⾯试机会，实在是很可惜。

为此，我写了这份《程序员写简历指南（保姆级）》专栏，多达⼏万字，帮⼤家了解：

如何写⼀份规范的程序员简历？

如何在简历中增加亮点？

有哪些常⻅的简历问题？

如何利⽤写简历来提升⾃⼰？

在投递简历或者找他⼈帮忙看简历之前，请先把本专栏⼀字不差地完整阅读⼀遍，并且根据建议先⾃⾏修改简历，从⽽增加回复率。

对于不急着找⼯作的朋友，我也建议尽早准备⼀份简历，并且随着学习持续完善和优化，毕竟机会总是留给有准备的⼈。

这是专栏第三章：简历问题和建议汇总。

⻥⽪花了整整4个晚上，对最近改过的⼏百份简历进⾏了逐⼀分析和梳理，最终整理出了⼀份⼤家写简历时经常出现的问题汇总⽂档，多达50多个⾼频问题！希望⼤家写简历前，都能⼀字不差地读完⼀遍这些问题，相信能够帮⼤家提升简历回复率。

# 1、整体

# 1.1简历篇幅过⻓

建议：⼀般校招简历以⼀⻚纸为最佳，保证⾯试官有耐⼼看下去。但注意，并不是说强制⼀⻚纸，只是希望⼤家在简历上突出重点、惜字如⾦，⽽不是像记流⽔账⼀样什么都写。如果你能写的内容就是很多的（⽐如冲击⼤⼚、⼯作3年以上、求职等级较⾼），那么⼀⻚纸以上完全没问题。

# 1.2简历缺少XX板块

建议：⼀份完整的程序员简历包含个⼈信息、教育背景、专业技能、荣誉奖项、⼯作经历、项⽬经历、科研经历、校园经历、个⼈优势等内容。

其中，个⼈信息、教育背景、专业技能、项⽬经历是必须具备的！

# 1.3简历篇幅不够合理

建议：合理分配各部分内容占⽤的篇幅，推荐的占⽐如下：

个⼈信息 $5 \sim 1 0 \%$ 

教育背景 $1 0 \sim 1 5 \%$ 

专业技能 $2 0 \sim 3 0 \%$ 

项⽬经历 $3 0 \sim 4 0 \%$ （⼯作/校园/科研等经历也算在内），对绝⼤多数同学来说，这部分是核⼼！

其他内容 $0 \sim 2 0 \%$ （⽐如奖项、个⼈优势等）

总之，尽量多写经历来体现⾃⼰的实践能⼒、解决问题的能⼒，少写⼀些正确的废话（⾃我评价）。

# 1.4简历模板不够整洁

建议：⼀份优秀的简历必须在外观和内容上都很出⾊，做到秀外慧中。所以，挑选⼀个好的简历模板是⾄关重要的！

简历的板块划分要清晰、排版要整洁、内容不要太挤或太空；⾊调不宜过暗或过亮，推荐蓝⾊或淡灰⾊；⾊彩不要太丰富，要让⼈看起来舒服。

可以尝试⻥⽪⾃⼰⽤过的、⾮常精简整⻬的免费简历模板：

https://www.laoyujianli.com/template/1685547340318179330 

当然也可以尝试其他模板，只要保证简历的整体结构是从上到下、布局清晰、排版整⻬、简洁⼲净就好，拒绝花⾥胡哨的⾊块和图标。

# 1.5简历⽂件命名或格式不规范

建议：简历⽂件的命名虽然没有绝对的规范，但是要仔细查看岗位描述是否有⽂件名规则的要求。

注意！除公司特别要求之外，⽂件格式⼀定要⽤PDF！！千万不要⽤Word！！！因为使⽤Word可能会因为打开软件的版本不同⽽出现预期之外的排版错乱，这个影响是致命的。

# 1.6简历中出现错别字

建议：整个简历中千万不要有错别字！尤其是技术名词或者专业术语。否则会给⼈感觉⾮常不认真，竞争激烈时搞不好直接就挂了。

所以写完简历后，⼀定要⾃⼰通读⾄少 3 遍，保证⾏⽂通顺、且⽆任何错别字！

# 1.7简历没有明确的重点或求职⽅向

建议：整个简历⼀定要有⼀个明确的、和求职岗位匹配的⽅向。

我认识⼀些学的技术⽐较多的同学，他们可能⼜会Python⼜会Java⼜会前端，写到简历上的项⽬也是各⽅向的都有，然后⼜没有在简历的开头注明“求职意向”，就导致⾯试官完全不知道他要找哪个⽅向的⼯作。

并不是说会的技术、写简历上的技术太多了不好，⽽是要有⼀个侧重点。⽐如找Java岗位的⼯作就把Java项⽬放最上⾯，⽤更多的篇幅去介绍。也建议⼤家找⼯作前越早明确⽅向越好，不要到最后什么都只学了⼀点，反⽽平平⽆奇了。

当然，如果你⾃⼰在多个⽅向学得都不错，可以准备多份不同的定制化简历，并根据不同的岗位、公司和岗位描述来调整优化简历（⽐如增加部分细节、调换内容的顺序等）。

⽐如你前后端都会，投递后端开发岗位时，把后端技术放在前端技术上⾯去写，项⽬经历、实习经历等都要侧重于后端。

# 1.8技术名词⼤⼩写错误

建议：技术名词最好严格控制⼤⼩写，⽐如数据库技术写 “MySQL” ⽽不是 “mysql”，从微⼩的细节中体现你的专业性。

# 1.9⽤词不专业或不凝练

建议：简历上的每⼀个词汇，都能够反映出你的⽔平。

很多同学的简历⽤词⽐较随意，⽐如“我⽤axios库完成了对数据库的查询”。

其实⼤家都⼼知肚明，axios是⼀个前端请求库，可以和后台进⾏交互，实现对数据的查询和管理。

但上⾯那个表达，语⾔不够清晰和凝练，还可能会给⾯试官⼀种感觉：你真的知道axios是什么？你真的和后端联调过么？

所以，⼀定要保证简历上的每个词都要准确，不能产⽣歧义。另外，尽量减少⼝语化的内容，不说⽤xx技术做了xx，⽽是⽤（基于）xx技术实现了xx。

# 1.10 内容重复

建议：简历中（尤其是项⽬和⼯作描述中）尽量不要出现重复的内容，不仅占⽤了空间，还会让⾯试官感到疲惫。

# 1.11简历内容过于简单

建议：当你简历上没有什么可写的内容、⼜必须要尽快投递简历时，可以适当包装。

注意，此处的包装不是指改变⾃⼰的学习、⼯作年限等（这种属于“隐瞒和欺骗”，⼀般不建议这么做），⽽是指适当夸⼤。

毕竟写简历的本质就是：如何以⼀种吹⽜⽪的⽅式尽量表现出你的能⼒。

虽然写简历要真实，但不能太⽼实！尤其是对于没有⼯作经历、项⽬经历、荣誉奖项的同学，要学会适当包装、合理包装。

⽐如尝试将你⽬前正在学的技术从“了解”改为“熟悉”，或者把你还没来得及实现的项⽬功能先提前写上去等等。

但是，不要过分包装，⽽且既然你提前把⼀些内容写到了简历上，就要加倍努⼒赶紧去真正学会/实现它。

# 1.12简历内容很多，但没有突出重点

建议：在写简历时，可以将部分内容⽚段进⾏加粗，或者多去写某部分的内容，来吸引⾯试官去提问。

⽐如：

1.⾃⼰掌握的很好技术名词

2.⾃⼰项⽬中⼤量运⽤的技术

3. ⾃⼰项⽬的优化成果数据

4.获得的名词较⾼、含⾦量较⾼的奖项

5.其他同学很少接触到的新技术或深⼊知识点

# 1.13部分语句不通顺

建议：你写在简历上的每⼀句话都有可能会暴露你的思维逻辑能⼒，所以必须保证语句通顺、逻辑合理。

# 1.14简历空间没有合理利⽤

建议：除⾮你实在写不满⼀⻚纸，否则简历上的所有内容都要做到“惜字如⾦”。能只⽤⼀⾏写完的内容，就不要换第⼆⾏再加那么⼏个字。另外，简历上尽量不要出现空⽩，⽐如⼀⾏只写了半句话、或者只占⽤了半⻚纸等。

实在不知道写什么，就去参考下别⼈的简历，并且⾃⼰再多学习⼀些技术、做⼀些项⽬。

# 1.15简历各板块的顺序不合理

建议：根据个⼈优势对各板块进⾏排序，把最有亮点的部分放上⾯。⽐如你的奖项⽐较多、但学历相对低了⼀些，就可以把奖项写在前⾯、学历放到最后去写。

# 2、个⼈信息

# 2.1个⼈信息占⽤的篇幅过多

建议：⼀般个⼈信息只占⽤简历整体 $5 \sim 1 0 \%$ 的篇幅即可。可以通过在⼀⾏内同时写多个信息来节约空间，并保证间距合理。

# 2.2照⽚不清晰/不端正

建议：照⽚要清晰端正，蓝底/⽩底/红底都可以，最好表情⾃然、⾯带微笑，尽量穿⽩衬衫或者正装，体现⼀个⼈的精神⾯貌。

# 2.3写了固定的期望薪资范围

建议：除⾮公司明确要求，否则不建议写期望薪资。原因如下：

1.很多公司的薪资还算公开透明，没必要写

2.可能你⾃⼰本⾝对某个⾏业的薪酬⽔平不了解，薪资写⾼了可能会错失求职机会

3.当你的表现或实际⽔平超出了你写的预期薪资范围时，会被⼈按照你的预期薪资来砍价，相当于把⾃⼰限制住了

当然，如果你要应聘⾼级岗位、或者对⾃⼰很⾃信，那么可以写⽐较⾼的期望薪资，从⽽过滤⼀些公司、猎头的打扰。

# 2.4 缺少个⼈相关链接

建议：因为简历的篇幅和内容有限，所以如果你的个⼈经历很丰富，推荐在简历上补充⼀些链接，⽐如个⼈⽹站、个⼈博客、个⼈作品集、代码仓库等，体现你的实践能⼒。

# 3、教育背景

# 3.1成绩排名⼀般

建议：⼀般排名⾼于前 $2 0 \%$ 的同学才建议在简历上写排名，否则没有优势。（尖⼦班除外）

# 3.2主修课程浪费了空间

建议：本⾝就是计算机相关专业（或者专业和求职岗位相匹配）的同学不⽤再占⽤空间去写⾃⼰的主修课程了，因为学校教的内容往往⽐较基础、⽽且⾯试官默认这个专业或者投递这个岗位的同学都应该会这些课，写上去也没有什么优势。

但是建议⾮计算机相关专业（或者专业和求职岗位不匹配）的同学适当列举关键主修课程，优先列举和求职岗位相关的、取得分数较⾼的课。

如果有得分较⾼的课程（⽐如90分以上），可以在课程名后⽤括号补充分数。

# 3.3存在学历造假⻛险

建议：除⾮迫不得已，否则不建议学历造假，因为⼤多数公司都是有背景调查的，哪怕通过造假顺利⼊职，也可能会被突然查出来并强制离职。

# 4、技术栈

# 4.1同⼀⾏列举了过多的技术名词

建议：写你会的技术栈时，尽量不要⽤特别⻓的⼀句话、像报菜名似的列举过多技术名词。建议采⽤列表的形式，每⼀⾏单独写⼀个技术的多个⼦知识点或者⼀系列相关的技术，做到把每⼀块技术写得更具体、清晰。

# 4.2XX技术写得过于简略，没有充分利⽤空间

建议：⼀般情况下，你掌握或熟悉的技术不要只写⼀个技术名词，⽽是建议利⽤好每⼀⾏的空间，多补充该技术中你掌握的知识点和技术细节，会让⼈觉得更真实、有说服⼒。

当然，如果某个技术你只是了解或听说过，就把你知道的知识点写上去即可。

# 4.3同⼀⾏列举了多个不相关的技术

建议：从简历的技术栈部分中不仅可以看出你学过哪些技术、掌握哪些技术，还可以看出你对技术的分类和知识点的梳理能⼒。尽量每⼀⾏写清楚⼀个技术，或者把⼀系列相关的技术放在同⼀⾏（⽐如SSM框架）；⽽不要把前端、后端、算法等知识点混在同⼀⾏去写。

# 4.4缺少你对XX技术的实践应⽤能⼒

建议：技术栈部分光写⾃⼰会什么技术、了解哪些知识是不够的，因为⼤多数⾯试官重视的是你的实践能⼒，即你能不能使⽤该技术完成⼯作，⽽不是纸上谈兵。因此可以适当补充半句：“你能⽤这些技术做什么？”，从⽽体现你的实

践能⼒。公司往往倾向于选择问题解决能⼒强、实践经验丰富的同学。

# 4.5 XX 内容过于基础，⽆法体现出你的能⼒

建议：尽量避免去写默认所有⼈都会的内容，⽐如Java的⼏种数据结构、前端HTML的标签、⾯向对象编程等。

# 4.6XX内容写得过于宽泛和模糊，缺乏可信度

建议：尽量不要写过于宽泛、模糊不清、⽆法证明的的内容，⽐如：

有⼀定后端基础

了解常⻅性能优化⼿段

有良好的开发规范

专业的⾯试官基本就默认当做你不了解、或者不具备这些能⼒。

你应当把这些宽泛的知识具体化，⽐如：

具备良好的编码能⼒ $= >$ 会⽤哪些开发⼯具、熟悉哪些编程技巧？

写得更具体⼀些，才会更有说服⼒。

# 4.7 各技术点的顺序不当

建议：和做短视频⼀样，我们要尽量把最吸引⼈的部分放在简历的最上⾯。所以建议优先把岗位描述中明确要求的、你学得最好的技术放在前⾯去写，和求职岗位关系没那么⼤的、仅是了解的知识点放到最后作为补充。

# 4.8技术栈和其他同学过于相似，缺少区分度

建议：哪怕⼤家都写同⼀个技术，你也可以写更多、更深⼊的知识点。

建议多阅读借鉴他⼈简历的技术栈部分，查漏补缺。

此外，平时除了学习主流技术外，最好能多去技术社区阅读⼀些技术⽂章，扩展⾃⼰的知识⾯。

# 5、荣誉奖项

# 5.1未重点突出⾼级别、⾼含⾦量的奖项

建议：获得奖项的级别或含⾦量很⾼时，建议把奖项级别加粗来吸引⾯试官，⽐如XX竞赛全国⼀等奖。

# 5.2 奖项未排序

建议：优先把认可度⾼的、参赛范围⼴的、获奖级别⾼的、和求职岗位更相关的奖项放上⾯，⼀些不知名的竞赛放到下⾯或者合并去写。

# 6、⼯作经历（实习经历）

# 6.1⼯作描述过于简单

建议：写⼯作内容时，可以适当具体⼀些，⽐如补充你在这家公司⽤了什么技术、负责了什么样的项⽬、使⽤过什么⽅法和⼯具、解决过什么问题等，从⽽增加真实感。

# 6.2⼯作内容和求职岗位关系不⼤

建议：简历应当围绕求职岗位去写，重点去写求职岗位相关的经历。当然，如果有能证明你能⼒的其他⼯作经历，也可以简略说明，但不能占⽤过多篇幅。

# 6.3 缺少⼯作成果和个⼈价值的体现

建议：尽量不要写⾃⼰在⼯作中收获了什么、学到了什么，⽽是多写⾃⼰做了什么、做出了什么成果，尤其是列举有明确数据的成果，⽐如“写过XX篇⽂档、做过X场技术分享、给项⽬带来了多少的收⼊增⻓”等，将更能体现⾃⼰的能⼒和价值。

如果⽬前没有可写的成果，建议在之后的⼯作中多思考如何积累这些内容。

# 6.4 ⼯作职责不明确

建议：即使你在这家公司做了很多不同岗位的⼯作，也要有个重点突出的⼯作职责，⽽不是什么都写。

# 6.5 个⼈的⼯作内容不够突出

建议：写⼯作内容的时候尽量突出⾃⼰的地位，在合适的情况下，尽量能把“参与”改成“负责”或“主导”某⼯作。

# 6.6XX⼯作写得过于宽泛和模糊，缺乏可信度

建议：尽量让你的⼯作描述更有说服⼒，⽐如写“与产品经理⾼效沟通”，不如改成去写：“你是怎么实现和他⼈的⾼效沟通？”，⽐如⽤了什么项⽬管理⼯具？或者跟前端协作时⽤了什么接⼝管理⼯具？

# 7、项⽬经历

# 7.1项⽬⼯作描述的写法存在不⾜

建议：写项⽬的⼯作描述时，不要把所有内容混在⼀起，⽽是建议⽤列表的形式分点去写，每个⼯作/亮点独占⼀⾏，每⼀点尽量具体。写的越具体，往往越体现真实性。

可⽤STAR分析法（场景、任务、⾏动、成果）来梳理⾃⼰的核⼼⼯作。

提供2个标准句式，括号部分表⽰可选填：

1.（在xx公司xx项⽬中，）在xx情况下，运⽤xx技术，解决了xx（或者优化了xx），达到了xx效果（或者带来xx收益等）。

2.为了解决xx问题，选⽤xx技术（或⽅法）实现了xx，并使⽤xx技术（或⽅法）优化了xx，实测提升了xx性能（或者降低了xx等）。

举个例⼦：为适应产品特性、加快迭代速度，后端由Springboot重构⾄Node.js，数据库由MySQL迁移⾄MongoDB，实现了前后⼀体的集中式配置中⼼，提⾼了接近1倍的开发效率。

注意每个⼩点的⻓度不宜过⻓，要留给⾯试官提问的空间。

# 7.2 技术栈提到的技术没有在项⽬中运⽤

建议：技术栈⾥提到的技术和知识点尽量多在项⽬经历中体现，否则容易给⾯试官⼀种“只是学过或听说过，⽽不会运⽤”的感觉。

# 7.3项⽬技术或业务相似度过⾼

建议：尽量不要写运⽤了太多重复技术栈、或者业务相似的项⽬，最好能够让各个项⽬形成互补。

前端的话可以考虑⼀个PC端 $^ +$ ⼀个移动端项⽬或者技术类项⽬（脚⼿架、组件库等）；后端可以考虑⼀个业务系统（⽐如管理系统、电商、社群、博客等） $^ +$ ⼀个技术类框架（⽐如RPC、迷你Spring、服务器等）。

# 7.4项⽬过多

建议：注意，写到简历上的项⽬不是越多越好！建议重点去写2-3个不同技术栈、不同业务场景的项⽬。

⼀个功能完整的、描述清楚的、实际上线了的项⽬可能都⽐你写⼏个不上线的⼩ Demo 更有说服⼒。

当然，如果你每个项⽬做的都很好，实在⽆法取舍的话就都写上吧~

# 7.5项⽬介绍太⻓

建议：注意每个项⽬⾥内容的⽐重，项⽬介绍的占⽐不要太多，⼀般1-2⾏⾜够了。

记住，你不是在做推⼴！在简历中，⾯试官更关注的是你在项⽬中负责什么、做了什么、怎么通过技术和设计能⼒去解决问题的。⾄于项⽬本⾝的介绍，⽤⼀两句话直击核⼼就好，重点在于交代和你⼯作有关的内容，其余的可以在⾯试时展开介绍。

# 7.6项⽬⼯作描述过于直⽩平淡

建议：要想项⽬有亮点，需要深⼀度。不能只写你完成了什么⼯作，⽽是要有⼀定的优化和扩展，让整句话读起来有起伏和递进。

⽐如你可以在完成某功能的基础上进⼀步优化，或者改造现有的项⽬框架、推陈出新，或者提升系统各⽅⾯的性能（可⽤性、稳定性、⽤户体验、吞吐量、时延等）。

建议⼤家多去了解你项⽬中⽤到的技术的同类技术，对这些技术的优缺点和适合的应⽤场景有个⼤致的印象。

# 7.7 项⽬没有提供可访问的线上地址

建议：条件允许的话，强烈建议提供可在线访问的项⽬地址（域名尽量简短，好让⾯试官访问），从⽽体现你项⽬的真实性，将会是⼀个⾮常不错的加分项。

因为绝⼤多数同学写项⽬经历的时候，不放已上线的项⽬地址。有的时候你写的点再多、吹得天花乱坠，都不如直接放⼀个可访问的项⽬地址来得实在，能够直接证明你真的做过这个项⽬、从⽽体现你的项⽬经验。对于前端同学来说这点更重要，直接给⾯试官看体验效果最实在。你做的⽹站⽤不⽤⼼，⼀看便知。

建议：写你在项⽬中的⼯作和技术运⽤时，最好能结合具体的业务去写，不要说写的所有内容都和你的项⽬本⾝关系不⼤、过于通⽤，即放到其他任何⼀个项⽬⾥都可以这么写。

建议：各项⽬的⼯作描述中尽量不要出现重复的内容，不仅浪费了空间，还会让⾯试官感到疲惫。

建议：其实绝⼤多数同学都是跟着⽹上的教程做项⽬，但同⼀个项⽬，也有⾼下之分。

# 从哪些⽅⾯优化项⽬？

⽅法：缓存、并发编程、异步、限流降级熔断、有损服务、CDN、数据压缩等

⽅法：⼈⼯分析删除、定期删除、低频存储、淘汰策略、数据压缩等

实际开发项⽬中，⼀定要有成本意识！很多同学光说优化，不考虑实际情况，这是⼀个错误的思维。

3）可⽤性：尽可能地提⾼系统对外提供服务的时⻓，即提⾼SLA（3~5个9的⾼可⽤）

参考⽂章：https://blog.csdn.net/terrychinaz/article/details/112976266

⽅法：集群、主备、⾃动故障恢复、监控告警、容灾

4）可靠性：尽可能地让系统提供可靠的服务，不要出现崩溃中断

⽅法：集群、主备、异常处理、降级、容灾

7）健壮性：系统不会因为部分异常⽽整体崩溃

⽅法：设计模式、架构设计、集群、分库分表、技术选型
